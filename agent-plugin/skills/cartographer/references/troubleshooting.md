# Troubleshooting

| Symptom | Fix |
|---|---|
| `map_*` tools missing | The plugin's MCP server couldn't start: install the binary (`mise use -g github:shermanhuman/cartographer`) and start a new session. |
| `unknown command "project"` or `"refresh"` | The binary predates 0.2.0: install 0.2.0 or later (`mise use -g github:shermanhuman/cartographer@0.2`), then start a new session. |
| Map tools work in some repositories only, or not at all | The plugin's launcher runs the cartographer that mise resolves from the global config (`mise which cartographer`, never installing). Without one it runs a non-mise build on `PATH`, never a mise install or shim, so a stale version can't start; with neither it exits 127. Pin it globally: `mise use -g github:shermanhuman/cartographer`, then restart the session. |
| "no map is available yet", "no map yet" or "this repository isn't covered by any map" | Nothing is registered for this repo. Registering is the user's: see *When the map can't answer* in `SKILL.md`. A 0.1 workspace's `workspace add <dir>` and `cartographer pull <owner/name>` are the user's to run. |
| "no map of project … yet" | The project is registered and its first build is running, waiting or failed; the message says which. Call again shortly, run `cartographer refresh`, or read the failure it names. Don't register it again. |
| Answers come from another project | `cartographer status` shows the snapshot in use; the map is chosen by the repository you're in. |
| Pull fails with 401/404 | The workspace repository is private: `gh auth login` (or set `GH_TOKEN`) with access to it. |
| Many ⚠ marks, "N files differ from the map" | For a registered project the map is each member's default branch as last fetched, and ⚠ marks files your checkout has changed relative to it (a branch, commits ahead, uncommitted edits); it refreshes on use at most every 15 minutes, or `cartographer refresh` now. A header saying "your checkouts" is a `--head` map built from working copies. For a 0.1 workspace: `cartographer build --local --import`, or `cartographer pull`. |
| "… failed at settings …: no .cartographer/repo.toml on its fetched branch" | That member has no settings on its default branch. If the checkout already has the file, merge that one; otherwise `cartographer project init <checkout> --project NAME --anchor owner/name` writes a starter file. Either way it reaches main through a pull request the user merges. The previous map keeps answering meanwhile. |
| "… failed at settings …: … names project \"x\", not \"y\"" or "… names anchor …" | The member's `.cartographer/repo.toml` disagrees with the anchor's list: fix its `project` or `anchor`, or, if it doesn't belong in the project, remove it from the anchor's `members`. `project init` refuses an existing file. |
| "behind the fetched commits: <repo> failed at <step>" in the header | Read the log it names. Usually a language pin is missing from the repo's own mise config, or an extractor failed. Fix it on main; the same inputs are retried after 6 hours, at the next fetch that finds a new commit, or by `cartographer refresh`. In a 0.1 workspace the header says "last rebuild failed" instead: fix the cause and run `cartographer build --local --import`. |
| Codex `exec` refuses map tools ("approval policy is never") | Allow the server's tools in Codex config: `plugins.<plugin>.mcp_servers.<server>.default_tools_approval_mode = "approve"`, or answer with grep in non-interactive runs. |
| Codex hooks don't fire | Codex runs plugin hooks only after you trust them in `/hooks`; `codex exec` skips them. The map tools still work. |
